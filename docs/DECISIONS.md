# Decision Log — Duramax LLY Engine Lab

Every settled decision lives here, newest last. To change the plan: add an entry here explaining the change and revise `docs/PLAN.md` in the **same pull request**. A decision is not changed until both are done.

## 2026-11-12 — Project definition

- **D-001 Project:** Build an interactive 2005 Duramax LLY engine lab — running engine, variable throttle, exploded/cutaway/x-ray views, swappable parts, dyno with stock-vs-modified comparison. Explicitly **not** a driving game.
- **D-002 Cost constraint:** Free tools and services only. No paid software, assets, or hosting.

## 2026-11-12 — Platform and stack

- **D-003 Platform:** Web app (runs from a link, any device), hosted on GitHub Pages. Desktop wrapper (e.g. Tauri) is a later option using the same assets.
- **D-004 Stack:** Blender (modeling) → glTF/GLB (asset format) → TypeScript + Three.js (app) + Vite (tooling), Git/GitHub (storage + CI), Poly Haven / ambientCG (free CC0 lighting/materials).
- **D-005 Three.js version is pinned.** An API-notes file accompanies every coding spec so AI-written code targets one API version.
- **D-006 Alternatives set aside:** Babylon.js (credible, but no advantage worth switching), Godot (game engine; heavy web export), Unity (heavyweight, license history), Unreal (poor web support), Python as app runtime (kept for Blender scripts and math prototypes only).

## 2026-11-12 — Architecture

- **D-007 Layered architecture:** (1) math/simulation core driven by crank angle, (2) parts catalog data, (3) performance model, (4) Three.js renderer, (5) web UI. Only the renderer imports Three.js; the core and performance model must run headless in tests.
- **D-008 Parts as slots + variants:** every swappable part is a slot with shared mounting datums; each variant carries a visual model **and** performance parameters **and** compatibility rules in one catalog entry.
- **D-009 Generic part tiers,** not brand names (brand performance data is mostly marketing claims).
- **D-010 Frozen interface contract:** the shared types/interface file changes only through a spec revision, never inside a feature change.
- **D-011 Asset contract:** concept-set coordinate frame is master (origin = crank axis at rear adapter plane, +X front, +Y LH, +Z up); Z-up→Y-up conversion once at glTF export; meters everywhere; every moving part's origin on its rotation/slide axis; naming `<system>_<part>_<instance>_<variant>`; motion driven by code, never Blender animation.

## 2026-11-12 — Simulation and performance model

- **D-012 Unknown dimensions are labeled placeholders** in a single config file, each with value, status, confidence, and source. The app labels illustrative geometry on screen (including generic valve timing/lift). No dimension is ever silently invented.
- **D-013 Performance model is fuel-first with limits:** fuel delivered sets torque; smoke (AFR), EGT, turbo map, CP3 capacity, and tune caps limit it. The dyno displays **which limit is binding** at each RPM and shows an **uncertainty band**, not a single line.
- **D-014 Variable-geometry turbo modeled explicitly,** with vane position as an input from the tune.
- **D-015 Dyno is educational with credible estimates,** not engineering-predictive. Output is crank (flywheel) power by default; wheel power only via an explicit labeled drivetrain-loss setting.
- **D-016 Stock rating keyed by transmission,** default **Allison automatic: 310 hp @ 3000 rpm, 605 lb-ft @ 1600 rpm** (manual: 300 hp / 520 lb-ft). Source: GM Media release 2005-08-01 via The Diesel Page (secondary host, medium-high confidence). Published figures of 520/590/605 lb-ft conflict because they describe different configurations/years.
- **D-017 Compression ratio 17.5:1** adopted from published LLY references (2004–2005), medium confidence.

## 2026-11-14 — Milestone 9 spec

- **D-040 Engine sound (Milestone 9).** Engine sound is a **procedural Web Audio synthesis** in a new `src/audio/` layer — zero sampled loops, zero audio files, zero new npm dependencies, no AudioWorklet/ScriptProcessor. It reads only existing state: `CrankState.rpm` for firing rate, the shipped Throttle (RPM) control's normalized travel for throttle/load, and the existing `computeDetails` output for the current build's boost and fuel. `src/core/**` (the D-010 interface) and `src/perf/**` are **unchanged**; sound never feeds the simulation, dyno, renderer, or catalog. The synthesis is: a 64-harmonic firing pulse train at `rpm/15`; half-order idle lope (`firingHz/8`) plus a 0.37 Hz drift; band-passed seeded-noise combustion/injector clatter amplitude-modulated at the firing rate; and a 3rd-order turbo whistle from a 20,000–115,000 rpm shaft-speed proxy (the literal 11-blade BPF is a low-level low-passed secondary layer). **Autoplay/lifecycle:** no `AudioContext` exists until the user presses the Sound control; sound is off on every load; the control is an `aria-pressed` mute/unmute toggle; the context suspends **immediately** when the tab is hidden, and **after the 0.12 s fade + 180 ms timer** when paused or in slow motion; mobile gets a ≥44 px control and an iOS `audioSession.type = 'playback'` opt-in when available (silent-switch behavior is documented and verified on a device). **Budgets:** no new assets; added production JS ≤ 12,288 B minified / ≤ 5,120 B gzip (measured planning prototype 3,954 / 1,735 B at gzip level 9, pure model + graph construction as a lower bound); audio update ≤ 100 µs/call from the 100-call benchmark batch and frame p95 within 0.30 ms of the sound-off run; 21 permanent nodes. The sound is **illustrative**, not an LLY recording and not dB-calibrated.

## 2026-11-14 — Milestone 11 spec

- **D-043 Capped-solid cutaways (Milestone 11).** The Section view's cut faces are produced by **runtime cross-section extraction and triangulation**: for every clipped part (with the 32 helical valve springs capped through a closed convex-hull proxy rather than their wire surface, so no part is left uncapped), the CPU intersects the part's triangles with the plane, welds the segments into closed loops, classifies holes, triangulates with three's `ShapeUtils.triangulateShape`, and writes the result as a flat, hatched, single-colour cap mesh at the plane with real depth. Static sources (exterior shell, cylinder heads, injectors, main shaft, external variants) rebuild only when the plane/explode/variant/exterior/x-ray state changes; dynamic sources (pistons, rods, crank throws, bridges, rockers, pushrods, lifters, valves, and the spring hull proxies) rebuild every frame. **Appearance:** one unlit cut-bronze section colour (`0.290, 0.170, 0.086` linear) with a 45° plane-locked hatch (5.0 mm spacing) carried by a per-vertex section-UV attribute; the cap communicates the plane, solidity, and that the face is diagrammatic, not a part material or a verified surface. **Scope:** all clippable parts; the 32 springs use *local* convex-hull proxies, and the 5 non-watertight shell partIds are closed by a local chord in the plane — neither is the rejected global hull route; the cap is the solid cross-section of the model, so enclosed cavities are filled and a shell-crossing plane legitimately hides internals behind it (X-Ray or Exterior-off shows them). **Interactions:** live with the slider (static set rebuilt at most once per frame), correct under explode (dynamic set per frame), x-ray suppresses shell caps, exterior toggle and variants need no special code, label rules unchanged. **Budgets:** +2 draw calls, cap triangles capped at 16,000 and measured, CPU rebuild targets ≤ 8 ms desktop / ≤ 16 ms phone static and ≤ 6.5 ms / ≤ 13.0 ms dynamic (hull-inclusive projection ≈6.1 ms), measured by the build; the renderer stats type gains additive, optional cap fields (`sectionCap*`), which does not touch D-010; no D-033 budget is raised, no stencil buffer, no render target, no extra render pass, no new dependency. **Rejected:** stencil-buffer capping (+616,520 submitted triangles full-scene, +208,024 for the smallest proof-covering subset — both tiers breach the submitted-triangle cap; requires a stencil context), the shader back-face fill (prototype: +0 calls/+0 triangles but a flat wall over intact geometry — 4–42 % of pixels changed depending on threshold, an independent diff gave 4.23 % at RF-6 — at ≈2.7–3.2 ms GPU; not a cap), and convex-hull proxies (46.9 % overfill vs the true shell section at X = 402.5 mm). **Visual proof:** RF-6 re-baselined, RF-14 (cut piston), RF-15 (cut head), RF-16 (sectioned exterior shell), RF-17 (longitudinal Y = −185 cut), each with a numbered checklist that fails on any visible hollow interior. **UI:** the "capped solid sections come later" note is replaced by "Section cut faces are filled as solid, hatched material — a diagrammatic section, not a machined or verified LLY surface." and the subtitles become `Milestone 11 — Capped-Solid Cutaways`.
